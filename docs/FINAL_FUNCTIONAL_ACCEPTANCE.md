## 修复范围

- `web/functions/question-merge.mjs`。规范化题号括号与子题标签，优先精确匹配。子题只在唯一、清晰的原卷父题中按明确且不重复的小问标记提取原文及共享条件。不同子题的作答和老师批改各自保留。无可靠原文的子题保持待人工核对，原图可定位时仍提供原图。保留已有人工确认的 ID 和版本。
- `math_service/main.py`、`math_service/verifier.py`。本机测得导入 SymPy 1.14 约 4.18 秒，有理不等式通用求解约 0.74 秒，等价的有理数精确求解约 0.011 秒。原方案每批创建进程，三次隔离基线约 4.58–4.76 秒，上一轮持续 HTTP 联测曾超过 7 秒。新方案最多两个可复用、可终止的隔离进程，分别计入启动和求解时限。冷调用约 4.01–4.09 秒，热调用约 0.07 秒。保留定义域、极点及端点精确检查。
- `web/functions/math-client.mjs`、`web/functions/learning-routes.mjs`、`web/pages/Learning.tsx`。核验结论继续区分通过、确定失败、未支持和超时。网关超时、容量满和工作进程失联可按同一版草稿重试，仍受审核门槛约束。
- 更新既有套件 `web/dev/multipage-recognition-test.mjs`、`web/dev/learning-flow-test.mjs`、`math_service/test_verifier.py`。
- `web/functions/model.mjs` 和 `web/functions/learning-routes.mjs`。首轮公网样例报告独立审核响应截断。原兼容规则遗漏百炼地域工作区域名 `*.maas.aliyuncs.com` 和 DeepSeek V4.1 型号。修复根据百炼官方接口说明在已有支持的模型上关闭思考输出，并将独立审核输出上限由每项 1000 提至 2000 token。保留原审核模型、模型独立性检查和审核发布门槛。[百炼 DeepSeek API 参考](https://help.aliyun.com/en/model-studio/deepseek-api)

## 人工复验步骤

1. 在公网学习工作台创建一个明确标识为自制验收的任务。原卷栏上传 `web/dev/fixtures/cloud-smoke/paper-1.png` 和 `paper-2.png`，答题卡栏上传 `sheet-1.png`。
2. 开始识别，核对第 2 题与第 7 题的两个小问。两个小问应分别指向原卷第 2 页及答题卡第 1 页。第 7(1) 题是最小值，第 7(2) 题是求 f(4)。如果 OCR 缺失明确小问标记，使用原图人工补齐。
3. 仅对照原图确认第 7(1) 题的作答和红叉，保存后到诊断页选择该题。检查错因报告引用原作答步骤或题设条件。
4. 完成针对性练习，交卷前检查题解不可见。进入讲解查看独立审核和数学验证结果；若未完成核验，保留该状态并查验原因。
5. 完成变式复测，刷新后确认报告仍显示当前作答、前后对比和“本次通过”或“仍需练习”。
